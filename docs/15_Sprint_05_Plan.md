## Sprint Goal

讓使用者能在完全本機的環境中匯入一種指定的信用卡月結帳單 PDF，
先檢查與修正候選資料，再明確選擇建立新交易、連結既有交易或排除，
實際降低手動記帳負擔且不讓不確定資料污染正式財務數字。

## 已確認範圍

### 納入

- 來源中立的匯入批次、來源觀察、待確認候選及正式交易來源關聯。
- 多個來源觀察可連結同一筆正式交易的資料結構。
- 第一個 adapter：永豐信用卡月結帳單文字型 PDF。
- PDF 開檔密碼一次性輸入、完全本機解析、不保存原始 PDF、完整原文
  或密碼。
- 國內、外幣、退款／扣抵、跨頁、摘要換行、零元、表尾總計與不支援
  版面的安全解析。
- 使用者檢查與修改日期、正數金額、交易語意、摘要、信用卡帳戶與
  分類。
- 建立新交易、連結既有交易、排除，以及批次確認／批次排除。
- 同一檔案及同一來源觀察的重複防護；與既有手動交易的疑似配對。
- 信用卡退款與應繳／溢繳雙餘額模型。
- 帳單總額核對；差異只提示，不建立交易湊平。
- 只使用虛構 PDF 的自動化測試，以及使用者本機真實帳單的不留檔
  最終驗收。

### 不納入

- CSV parser（保留為下一個來源，不阻擋本 Sprint）。
- 掃描型 PDF、OCR、其他銀行或其他帳單格式。
- Email 收取、Gmail 授權、信用卡每日通知 parser、簽帳金融卡通知
  parser 與即時通知狀態。
- 自動合併、自動覆蓋既有交易、完全自動入帳或雲端 AI 分類。
- 銀行直接連線、還原 UI、Electron 升級、G-01～G-06 完整實作。
- 保存原始 PDF、完整抽取文字或 PDF 密碼。
- 分期、授權未請款、沖正與 Email／月結帳單間的完整配對語意。

## 必要前置與範圍提醒

DEC-023 目前隱藏新的信用卡建立入口，但 PDF 匯入必須指定信用卡。
本 Sprint 只有限度恢復「建立信用卡及在匯入時選擇信用卡」；
不因此恢復帳戶轉帳、一般信用卡消費或信用卡繳款的完整進階入口。
此項已由使用者確認。

## 核心資料與行為

### 來源中立流程

```text
選取來源檔案
→ main 本機讀取並一次性使用 PDF 密碼
→ parser adapter 產生來源觀察
→ application 建立匯入批次與待確認候選
→ 使用者檢查／修改
→ 建立新交易、連結既有交易或排除
→ 只有建立／連結成功後才形成正式來源關聯
```

- parser 不得直接寫 Repository 或建立正式交易。
- renderer 不得取得檔案系統、Node、Electron 或 PDF 密碼保存能力。
- PDF 密碼只允許一次性跨窄 IPC 到 main；不得回傳、記錄或保存。
- 匯入候選確認前不影響帳戶、信用卡餘額、月統計或淨資產。
- 每次批次確認在 application 層使用單一持久化 transaction；其中
  任一建立、連結、排除或財務更新失敗時全部回復。

### 去重與配對

- 檔案內容摘要阻止同一 PDF 重複建立批次。
- 來源檔案摘要辨識完全相同的檔案；來源觀察指紋只使用必要的正規化
  欄位，不保存完整原文。兩者不得混成同一個去重鍵。
- 與既有交易比對時可使用日期範圍、正數金額、信用卡、摘要正規化
  與來源種類；確切權重及門檻必須在實作前以 domain 規則拍板。
- 高度相似時顯示相同與不同欄位並讓使用者決定，不自動合併或刪除；
  只有日期與金額相同不足以提出自動連結。
- 使用者選擇連結既有交易時，不修改該交易的金額、分類或摘要。

### 分類建議

- 優先採用使用者既有交易與明確規則。
- 無可靠證據時保持未分類／待確認，不猜測。
- 使用者可將交易以「暫未分類」確認；它在分類統計中獨立顯示，不能
  偷偷歸入「其他」。
- Sprint 05 不建立雲端 AI、模糊生成式分類或背景自動學習。

### 信用卡退款與雙餘額

- `credit_card_refund` 使用正數金額，不計收入。
- 消費、退款及繳款依 DEC-038 在應繳與溢繳間移動。
- 舊信用卡 `amount` 升級為應繳，溢繳為 0；migration 必須證明升級
  前後總資產、總負債與淨資產一致。
- 批次確認多筆消費與退款時，domain／application 的財務預檢必須以
  整批已選項目計算最終餘額，不得因陣列輸入順序產生假的「餘額不
  足」。這是計算語意，不等於已決定 persistence 必須 all-or-nothing。

## 執行順序

```text

階段 1　退款及信用卡雙餘額財務模型
```

# 階段 1　退款及信用卡雙餘額財務模型

# 階段 2　來源中立匯入核心與 persistence

## S5-20　Ports 與 use cases

- 定義 parser adapter、匯入批次、來源觀察、候選、正式來源關聯的
  ports，不依賴 PDF.js 或特定銀行。
- use case 涵蓋建立批次、載入待確認、修改候選、建立新交易、連結
  既有交易、排除、批次確認與批次排除。
- parser mock 只能假裝來源輸出與儲存，不得手抄財務規則。

## S5-21　Persistence 與原子性

- 新增表格與索引，逐項對應實際查詢。
- 候選確認前不得出現在正式交易查詢與月統計。
- 建立正式交易與來源關聯必須同一交易；任一步失敗全部回復。
- 原始 PDF、完整抽取文字及密碼不得寫入任何欄位。

# 階段 3　永豐文字型 PDF adapter 與安全 IPC

## S5-30　正式 parser adapter

- 以虛構 fixture 重建原型已驗證的結構，不複製真實帳單內容。
- 解析限制涵蓋檔案大小、頁數、文字項目數與執行時間。
- 摘要跨兩行只在欄位一致、恰好兩段、來源索引連續且未使用時合併；
  其他情況 `special_review`，不得猜測。
- 帳單總計與自動扣款訊息不得被建立為消費候選。
- 掃描型、損壞、未知版面及解析不完整使用穩定錯誤／警告碼。

## S5-31　檔案選取、PDF 密碼與 IPC

- renderer 只提出選檔、解析與確認意圖。
- main 控制檔案對話框、讀取與 PDF 密碼生命週期。
- PDF 密碼不保存、不記錄、不回傳；原始路徑及底層錯誤不得跨 IPC。
- production bundle 不含固定測試密碼、真實帳單、主密碼或金鑰。

# 階段 4　待確認 UI 與使用者決定

## S5-40　匯入預覽

- 顯示批次來源、帳單月份、候選數、排除／特殊檢查數與帳單總額核對。
- 來源只有日期時顯示日期與「時間未知」，不顯示內部 12:00 技術值。
- 每筆可修改日期、金額、交易語意、摘要、信用卡與分類。
- 不以顏色或「信心」文字冒充確定性；警告使用穩定代碼對應中文。
- 遵守 `00_UI_Feedback_Rules.md`、鍵盤操作、可見焦點及 300 行／8
  state 限制。

## S5-41　確認、連結與排除

- 單筆與批次建立新交易。
- 連結既有交易時顯示欄位差異，且不修改既有交易。
- 排除保留來源檔案摘要與必要的來源觀察指紋，避免同一來源下次再次
  出現；不得因此保存完整原文。
- 批次任一操作失敗不得顯示成功，所有建立、連結、排除、正式財務
  影響與來源關聯全部回復。

# 階段 5　去重、配對與分類建議

## S5-50　同檔與跨來源去重

- 同一 PDF 重複選取不得建立第二個批次。
- 同一觀察跨帳單出現時提出疑似重複。
- 不確定時只能提示，不能自動合併、覆蓋或刪除。
- 測試相同檔案、不同檔名相同內容、相同金額不同交易、跨月退款及
  與既有手動交易相似等情境。

## S5-51　分類建議

- 只依已確認的既有交易或使用者規則提出建議。
- 多個分類同樣合理或證據不足時不提供建議。
- 所有建議可修改，且不得覆蓋使用者已選結果。

# 階段 6　驗收與 Review

## S5-60　自動化與安全驗收

至少執行：

- `npm.cmd run typecheck`
- `npm.cmd run lint`
- `npm.cmd run verify`
- `npm.cmd test`
- Browser E2E
- 同一份 package 的 Electron 測試連續 10 次
- package smoke、production bundle 敏感字串掃描、`npm.cmd run make`
- 最新安裝檔乾淨安裝與完全離線解析

必須另外證明：

- 故意改壞退款／雙餘額規則時測試會紅。
- 匯入候選確認前所有正式財務數字不變。
- 錯誤密碼、損壞 PDF、未知版面與 IPC 失敗不保存任何敏感內容。
- 同一 PDF 及同一交易不會重複建立。
- 國內與外幣虛構 fixture 可完整解析，帳單總額不被當成交易。
- 使用者在本機以真實 PDF 做最終驗收，但 repo、log、輸出與建置產物
  都不含真實內容。

## S5-61　Sprint Review

Review 至少回報完成內容、修改檔案、migration、IPC、套件與容量、
測試數量與實際輸出、敏感資料掃描、未完成項目、偏離計畫、已知風險
及下一個來源 adapter 的擴充成本。

## 已知風險

- PDF 版面可能在發卡機構未通知下改變；未知版面必須安全失敗。
- 文字型 PDF 的視覺列與文字抽取順序可能不同，不能只靠寬鬆 regex。
- 不保存原始 PDF 能降低敏感資料風險，但也限制日後重新解析與稽核；
  必須保留足夠的非敏感來源欄位與指紋。
- 相同日期與金額不代表同一交易；來源檔案摘要只能防完全相同檔案，
  來源觀察指紋只能提出疑似配對，兩者都不能取代使用者判斷。
- PDF.js 會增加安裝容量；安全版本、離線資產及 Electron 相容性優先
  於縮小體積。
- 正式 A/B 的 Setup 增量超過 30 MiB 時必須停止並重新審查，不得
  自行接受或以降低安全性換取容量。
- Electron 42 將於 2026-10-20 EOL；本 Sprint 不升級 Electron，亦
  不得為相容 PDF.js 放寬安全設定。
