# Sprint 01：可操作的淨資產底座

## 文件資訊

- 狀態：實作完成，待 Sprint Review
- 依據：`01_Product_Vision.md`、`02_Requirements.md`、`03_Business_Rules.md`、`04_Decision_Log.md`
- 對應決策：DEC-001、DEC-003、DEC-004、DEC-009、DEC-010、DEC-011、DEC-012
- 建議週期：1 週
- 資料限制：只使用假資料或匿名化資料

## Sprint Goal

完成第一個可執行的 Windows 桌面垂直切片，讓使用者能手動建立、查看、修改及停用資產與負債，資料在重新啟動應用程式後仍存在，首頁會依正式商業規則重新計算並顯示總資產、總負債及淨資產。

```text
手動建立資產與負債
→ 儲存資料
→ 計算淨資產
→ 首頁顯示資產與負債
→ 修改後重新計算
```

## 本 Sprint 納入範圍

### 1. 桌面應用基礎

- 建立 Electron Forge、Webpack、React、TypeScript 專案。
- 設定開發、測試、型別檢查及建置指令。
- Electron 啟用 `contextIsolation`，停用 renderer 的 Node.js 整合。
- renderer 只透過受限制且具型別的 preload API 呼叫應用功能。

### 2. 核心財務模型

建立不依賴 Electron、React 或特定資料庫的領域模型，至少包含：

- 項目識別碼。
- 名稱。
- 方向：資產或負債。
- 類型。
- 目前 TWD 金額。
- 資料狀態：已確認、推算、已過期、待確認。
- 最後更新時間。
- 是否啟用。
- 是否計入淨資產。

本 Sprint 使用單一 TWD 金額，不實作外幣換算。停用或設定為不計入的項目不得進入合計。

### 3. 資料存取

- 定義與儲存技術無關的財務項目 Repository 介面。
- 由 Electron main process 實作本機資料存取。
- 支援新增、查詢、修改及停用。
- 使用可版本化的 schema／migration 機制，保留未來替換或加入加密儲存的邊界。
- 正式加密完成前，僅允許假資料或匿名化資料。

### 4. 使用者流程

- 首頁顯示總資產、總負債與淨資產。
- 首頁顯示啟用中項目的主要組成、資料狀態與最後更新時間。
- 提供新增資產／負債表單。
- 提供編輯及停用項目的操作。
- 儲存成功後立即重新讀取並計算首頁數字。
- 表單驗證失敗或儲存失敗時顯示可理解的錯誤，不以零值掩蓋錯誤。

### 5. 自動化驗證

- 淨資產、總資產與總負債的領域單元測試。
- 停用及不計入項目的排除測試。
- 使用整數最小貨幣單位計算，避免浮點誤差。
- Repository 的新增、讀取、修改、停用整合測試。
- 至少一條完整使用者流程測試：新增資產與負債、檢查合計、修改後檢查重算、重新啟動後確認資料仍存在。

## 使用者故事與驗收條件

### US-01 查看淨資產

身為使用者，我希望開啟首頁便看到總資產、總負債與淨資產，以快速掌握目前財務狀態。

驗收條件：

- 合計符合 `淨資產 = 總資產 − 總負債`。
- 金額以 TWD 顯示。
- 無資料時顯示空狀態；空集合的合計可顯示為零，但不得把載入失敗顯示成零。
- 每個項目顯示資料狀態及最後更新時間。

### US-02 新增資產或負債

身為使用者，我希望手動建立財務項目，使尚未支援自動匯入的內容也能納入淨資產。

驗收條件：

- 必填欄位至少為名稱、資產／負債方向、類型與金額。
- 金額必須是有效且非負的 TWD 金額；資產或負債方向決定其計算方式，不以負數代表負債。
- 新增成功後，首頁合計及組成立即更新。
- 重新啟動應用程式後，資料仍存在。

### US-03 修改或停用項目

身為使用者，我希望修正或停用資料，使錯誤及不再使用的項目不會持續影響淨資產。

驗收條件：

- 使用者可修改名稱、類型、金額、狀態及是否計入淨資產。
- 修改成功後立即重新計算。
- 停用項目保留在資料庫，但不計入合計。
- 本 Sprint 不提供永久刪除，避免誤刪及破壞未來稽核能力。

## 建議工作拆分

### S1-01 專案骨架與安全邊界

- 初始化 Electron Forge Webpack TypeScript 專案並加入 React。
- 建立 main、preload、renderer、application、domain、infrastructure 的責任邊界。
- 完成安全 BrowserWindow 預設值與最小 IPC API。

完成定義：應用程式可啟動、型別檢查及測試指令可執行，renderer 無法直接使用 Node.js 或檔案系統。

### S1-02 領域模型與淨資產計算

- 定義 FinancialItem、Money、DataStatus 與計算服務。
- 實作 BR-001、BR-003 及本 Sprint 適用的 BR-010、BR-012、BR-013、BR-020、BR-021、BR-022。
- 撰寫正常值、零值、大額數字、停用及排除項目的單元測試。

完成定義：核心領域測試通過，且領域程式碼不依賴 UI、Electron 或資料庫套件。

### S1-03 本機持久化

- 定義 Repository port。
- 實作本機 adapter、schema 與初始 migration。
- 實作新增、查詢、修改及停用。
- 以暫存測試資料庫完成整合測試。

完成定義：資料可跨應用程式重啟保留，資料存取錯誤可向應用層回報。

### S1-04 資產負債管理介面

- 建立首頁數字卡與資產／負債清單。
- 建立新增及編輯表單。
- 加入停用與是否計入淨資產操作。
- 顯示資料狀態、更新時間、空狀態及錯誤狀態。

完成定義：使用者不需操作資料庫或檔案便能完成主要流程。

### S1-05 垂直流程驗證與文件

- 完成端到端或等價的整合流程測試。
- 執行 typecheck、unit、integration、build。
- 更新 README 的啟動與測試方式。
- 記錄本 Sprint 實際採用的技術決策及已知限制。

完成定義：以假資料完成新增、顯示、修改、停用、重啟保留的驗收示範。

## 已確認技術方向

以下方向已於 Sprint 開始前確認，正式決策記錄於 `04_Decision_Log.md`：

- 本機資料庫：SQLite。
- SQLite driver：Electron 所含 Node.js 的內建 SQLite API。
- 金額表示：以 TWD 最小貨幣單位的整數儲存與運算；介面層負責格式化。
- 資料存取：Repository 介面隔離 SQLite，migration 管理 schema。
- 測試：領域單元測試、Repository 整合測試，以及一條 UI 垂直流程測試。
- 永久刪除：本 Sprint 不提供，只提供停用。

選擇 SQLite 是因為它符合單一使用者、本機優先及可持久化需求；透過 Repository 與 migration 隔離後，可避免財務領域規則依賴特定資料庫，並為後續加密方案保留替換邊界。技術驗證後採用 Node.js 內建 SQLite API，避免額外原生 driver 對 Python、C++ 建置工具及 Electron ABI 的依賴。

## 明確不納入

- 股票／ETF 市價與匯率自動更新。
- 外幣換算與未實現損益。
- Gmail、銀行 Email、信用卡 PDF 或任何外部資料匯入。
- 收入、支出、轉帳、固定收支及月報。
- 支出分類、待確認中心及通知。
- 自訂類型管理介面；本 Sprint 先提供固定的 MVP 類型與「自訂資產／自訂負債」。
- 真實財務資料。
- 主密碼、完整資料庫加密、備份與還原。
- 雲端同步、外部 AI、多使用者。

## Definition of Done

- 所有驗收條件以假資料通過。
- `typecheck`、單元測試、整合測試及 production build 全部成功。
- 重要財務計算具有自動化測試。
- renderer 未直接接觸資料庫、檔案系統或 Node.js 完整能力。
- 沒有秘密、真實帳單、正式資料庫或敏感金融資料進入 Git。
- 新增的架構及技術選擇已記錄。
- README 包含本機啟動、測試及「不得使用真實資料」警告。

## 依賴、風險與待確認

### 不阻擋規劃

- 第一個 Sprint 不需要選定股票價格、匯率、銀行或信用卡帳單來源。
- 預設支出分類、待確認中心形式及匯出格式與本切片無關。

### 已確認

1. SQLite 作為第一版本機資料庫。
2. Sprint 1 採一週 timebox。
3. Node.js 內建 SQLite API 已通過 Electron Forge Webpack 的 Windows 封裝與啟動驗證。

### 已知風險

- Forge／Webpack／ESLint 開發工具鏈目前有 npm audit 傳遞相依警告；正式執行相依掃描為零，後續應追蹤上游更新，避免使用 `audit fix --force` 造成不相容降版。
- 完整加密尚未完成，因此 Sprint 產物不得輸入真實財務資料。
- Sprint 1 的單一 TWD 金額模型是刻意限縮；後續加入外幣與股票時，應擴充估值模型，不可把浮點數直接加入領域計算。
- 「帳戶」與一般資產／負債項目的長期資料模型仍需在後續使用回饋中細化；本 Sprint 應保持領域介面可演進，避免把 UI 表單直接等同資料表。

## Sprint Review 建議展示

使用完全虛構的資料：

1. 建立「示範銀行存款」TWD 1,000,000。
2. 建立「示範房產」TWD 8,000,000。
3. 建立「示範房貸」TWD 5,000,000。
4. 驗證總資產為 TWD 9,000,000、總負債為 TWD 5,000,000、淨資產為 TWD 4,000,000。
5. 將房貸修改為 TWD 4,900,000，驗證淨資產重新計算為 TWD 4,100,000。
6. 停用房產，驗證其不再計入合計。
7. 關閉並重開應用程式，驗證資料與計算結果仍存在。
