# FinanceHub 介面回饋規範

## 文件資訊

- 版本：1.0
- 日期：2026-07-31
- 狀態：**正式生效**
- 適用範圍：所有新建或修改的操作結果提示、警告與錯誤回饋
- 依據：使用者確認的 Sprint 04 備份介面呈現

## 1. 目的

使用者完成操作後，必須能立即分辨：

1. 操作是否仍在進行。
2. 操作成功、失敗或需要注意。
3. 結果影響了什麼。
4. 是否需要下一步處理。

禁止只用按鈕閃動、短暫文字變化或顏色表示結果。提示必須同時包含
圖示與可理解的中文文字。

## 2. 回饋種類

| 種類 | 圖示 | 文字與背景 | 使用時機 | 消失方式 |
|---|---|---|---|---|
| 成功 | 綠色圓形勾勾 `✓` | 深綠文字、淡綠背景 | 操作完整成功 | 約 3 秒後自動消失 |
| 失敗 | 紅色圓形叉號 `×` | 深紅文字、淡紅背景 | 操作未完成或結果不可用 | 保留至重試、離開畫面或使用者關閉 |
| 警告 | 黃色圓形驚嘆號 `!` | 深黃色文字、淡黃背景 | 主要操作成功，但有部分工作未完成或需要注意 | 保留至狀態解除、離開畫面或使用者關閉 |
| 資訊 | 藍色或中性色資訊圖示 `i` | 深色文字、淡色背景 | 不代表成功或失敗的狀態說明 | 約 3 秒後自動消失 |

不得只靠顏色區分。圖示只作視覺輔助時使用 `aria-hidden`；成功及資訊
使用 `role="status"`，會影響使用者下一步的失敗使用
`role="alert"`。

## 3. 顯示位置

### 3.1 主畫面

提示放在目前頁面標題正下方、主要內容卡片上方，不固定在整個應用
程式右下角。提示區預留穩定空間，出現或消失時不得讓主要卡片跳動。

### 3.2 對話框

對話框內操作的提示放在對話框標題下方或操作按鈕上方，不要顯示在
遠離操作位置的全域角落。

對話框本體必須使用不透明背景；只有後方遮罩可以半透明。背景文字
不得透過對話框而影響閱讀。

### 3.3 多則提示

同一情境一次只顯示一則主要提示。新結果取代同一操作的舊結果，
不得在畫面堆疊多個相同泡泡。持續性系統警告可以另列，但不得與
操作提示重複相同文案。

## 4. 文案規則

文案使用「動作結果＋影響」的順序，避免只有「成功」「失敗」或
「操作完成」。

正確範例：

- `備份已完成`
- `備份已完成，並已移除最舊的 1 份備份`
- `最新備份已匯出`
- `備份狀態已更新`
- `新備份已完成，但無法移除最舊的備份`

禁止在使用者文案顯示 SQL、SQLite、完整路徑、錯誤堆疊或內部錯誤
訊息。失敗文案必須由穩定錯誤代碼映射。

## 5. 非同步按鈕

- 操作送出後立即停用會造成重複操作的按鈕；main／application
  仍須保留真正的互斥防線，不能只靠 renderer。
- 備份、匯出等可能受資料量或裝置速度影響的操作，按鈕可改為
  `正在備份…`、`正在匯出…`，但必須保留固定或最小寬度。
- 毫秒等級的重新整理不切換成一閃而過的進行中文字；按鈕短暫停用，
  完成後顯示結果提示。
- 進行中、成功與失敗都不得搶走鍵盤焦點。

## 6. 延遲與生命週期

成功與資訊提示自動消失屬於刻意的產品延遲，可以使用
`setTimeout`。不得用相同方式等待 React 狀態、協調焦點、捲動或
修補競速；相關限制仍以 `00_Architecture_Rules.md` 第 6.1 節為準。

元件卸載或提示被取代時必須清除既有 timer，避免舊提示在其他畫面
重新出現。

## 7. 驗證要求

新增或修改提示時，至少以 E2E 驗證：

- 成功與失敗文字可見。
- 對應圖示／tone 樣式存在，不只顏色不同。
- 提示位於觸發操作的頁面或對話框情境內。
- 主要內容不因提示出現而發生不可接受的跳動或水平溢出。
- 失敗路徑必須實際觸發，不能只測成功。

目前備份頁由 `tests/e2e/backup-settings.spec.ts` 覆蓋成功、失敗、
警告位置、對話框不透明背景及窄畫面。

## 8. 既有介面的導入原則

「資料與備份」頁面是本規範的第一個正式實作。其他既有頁面的舊式
右下角通知不在本次文件工作中全面重構；後續修改到該操作流程時，
必須一併遷移到本規範，不得再新增另一套提示樣式。
